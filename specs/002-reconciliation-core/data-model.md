# Data Model: 002 Reconciliation Core

One forward-only migration (`0032_*`, generated by `pnpm db:generate`, never `push`).

## Schema changes (`packages/db/src/schema.ts`)

### `reconciliation_ignores` (new)
- `user_id` uuid not null (FK users, cascade), `source_fingerprint` varchar(64) not null, `external_id` varchar(255) not null, `reason` varchar(160) not null, `created_at` timestamp not null default now.
- PK `(user_id, source_fingerprint, external_id)`.

### `import_name_mappings` (new)
- `user_id` uuid not null (FK users, cascade), `description_key` varchar(160) not null, `name` varchar(160) not null, `updated_at` timestamp not null default now.
- PK `(user_id, description_key)`. Key = `getImportedDescriptionKey(line name)`; value = typed entry name.

### `reconciliation_batches` (new)
- `id` uuid PK (= batch id), `user_id` uuid not null (FK users, cascade), `target_type` varchar(16) not null (`account` | `card`), `target_id` uuid not null, `undo` jsonb not null (`ReconciliationUndoJournal`), `created_at` timestamp not null default now.
- Index `(user_id, created_at)`. Row deleted when undone.

### `recurring_transaction_occurrences` (extended)
- Add `import_source_fingerprint` varchar(64) null, `import_external_id` varchar(255) null.
- Partial unique index `(user_id, import_source_fingerprint, import_external_id)` where `import_external_id is not null`.

Unchanged and reused: `transactions.import_source_fingerprint/import_external_id/import_batch_id` (+ existing unique index), `import_category_mappings`, `settlement_events`.

## Domain types (`packages/domain/src/reconciliations.ts`)

- `ReconciliationTargetType = "account" | "card"`.
- `ReconciliationEntryRef = { kind: "transaction"; id: string } | { kind: "occurrence"; ruleId: string; date: string }` (series id resolved by the repository from the rule); `entryKey` string form `t:<id>` / `o:<ruleId>:<yyyy-mm-dd>`.
- `ReconciliationLine`: `index`, `identity: { sourceFingerprint; externalId }`, `purchaseDate`, `postedDate | null`, `signedCents`, `name`, `installment | null`, `lineKind | null`, `categoryName | null`.
- `ReconciliationEntry`: `entryKey`, `name`, `date`, `period`, `signedCents` (effective amount), `installmentCount | null`, `currentInstallment | null`, `externalId | null` (only when its source fingerprint equals the file's), `categoryId | null`, `isSettled`, `hasSplits`, `isTransfer`, `isGenerated`, `inPaidInvoice`, `isRecurring`.
- `MatchRule = "identity" | "installment" | "exact" | "cents" | "name-period"`.
- `LineClassification`: `{ status: "matched"; rule; entryKey; divergence: { appCents; fileCents } | null } | { status: "ambiguous"; candidateKeys } | { status: "bank-only" }`.
- `MatchSuspicion = { reason: "before-file-start"; entryDate; fileStartDate } | { reason: "amount-divergence"; appCents; fileCents }`.
- `AmountAlignment = { kind: "none" } | { kind: "align"; toCents } | { kind: "kept"; reason: "splits" | "transfer" | "generated" | "paid-invoice" | "card-recurring" }`.
- `ReconciliationBucket = "needs-decision" | "matched" | "bank-only" | "ambiguous" | "ignored" | "informational"` (+ app-only entries list, not lines).

## Plan and journal (`packages/domain/src/reconciliations-plan.ts`)

- `LineDecision = { lineIndex; action: "keep" | "create" | "link" | "ignore" | "skip"; entryKey?; name?; categoryId?: string | null; personId?; ignoreReason? }`.
- `ReconciliationPlan`: `creations[]` (line, name, signedCents, purchaseDate, period, categoryId, personId), `releases[]` (entryRef + identity), `stamps[]` (entryRef + identity), `alignments[]` (entryRef, toCents), `settlements[]` (entryRef, cents, date) , `ignores[]` (identity, reason), `categoryMappings[]` (key, categoryId, unique by key), `nameMappings[]` (key, name, unique by key).
- `ReconciliationUndoJournal` (stored jsonb, written by the repository from values read inside the apply transaction): `stamped[]` (ref + identity), `released[]` (ref + identity), `amountChanges[]` (ref, field `amount` | `settledAmount`, previous decimal string), `settledByApply[]` (ref; transfer pairs by transfer id), `stampOnlyOccurrences[]` (occurrence refs created just to hold an identity).

## State transitions
- Line: classified -> decided (UI, ephemeral) -> applied (stamped/created/ignored) -> undone (identity cleared or given back; ignore kept).
- Entry settlement (account): pending -> paid on apply (file value, posted date) -> pending on undo (only when `settledByApply`).
