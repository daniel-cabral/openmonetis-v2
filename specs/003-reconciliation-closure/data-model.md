## Schema changes (`packages/db/src/schema.ts`)

### `transaction_origin` pgEnum (extended)
- Add value `invoiceCredit` (last position). Generated SQL: `ALTER TYPE "public"."transaction_origin" ADD VALUE 'invoiceCredit';` (precedent `0007_narrow_bastion.sql`).
- `transactions_payment_method_origin_check` is unchanged: a credit has `payment_method = 'credit_card'` (non-null, as required for every origin except `accountBalanceAdjustment`).

## Invoice credit entry (a `transactions` row)

| Field | Value |
|---|---|
| `origin` | `invoiceCredit` |
| `type` | `income` (amount stored positive, as every income) |
| `payment_method` | `credit_card` |
| `card_id` | the reconciled card; `account_id` null |
| `period` | the invoice period of the reconciliation |
| `purchase_date` | the line's launch date |
| `is_settled` | null (card entry) |
| `person_id` | decision person, default admin |
| `category_id` | decision category or null |
| `condition` | `single` |
| `import_source_fingerprint`, `import_external_id`, `import_batch_id` | file fingerprint, line identity, reconciliation batch id |

Invariants: counted in the invoice total (`invoices.repository` movements, no origin filter); never in `invoice_payments`; never in income/expense aggregates (plan.md exclusion list); editable keeping `type`, `payment_method`, `card_id`; deletable; removed by `DELETE /reconciliations/{batchId}`; untouched by invoice payment undo/reopen (they delete by the payment's own `transaction_id`).

## State transitions
- Credit line: classified (matched / bank-only / ambiguous) -> created as `invoiceCredit` (apply) -> matched by identity on re-upload -> removed on batch undo; edits and deletes by the user like a regular entry.
- Projection (ephemeral, web): baseline + effects of the current decisions, recomputed on every decision; never persisted.
