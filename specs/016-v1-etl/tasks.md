# Tasks: V1 to V2 Data Migration (ETL)

**Input**: Design documents from `specs/016-v1-etl/` (spec.md with Clarifications and resolved
decisions, plan.md, research.md, data-model.md, contracts/cli.md, contracts/output-formats.md,
quickstart.md)

**Tests**: required by the constitution (principle V) and limited by `test-slop-guard`: each task
carries its `Test:` declaration. Unit tests are pure (`node:test` + `tsx`); one integration suite
`apps/api/src/v1-etl.integration.test.ts` (script `test:v1-etl:integration`, run from **bash**,
`VAR=1 tsx ...` fails in cmd) creates its own V1 fixture and V2 databases through
`apps/api/src/test-support/integration-database.ts`. While iterating run only the touched test files;
lint, typecheck and the full suite run once in T046.

**Conventions**: all code under `apps/api/src/scripts/v1-etl/` (fork-only operator tool; research
R1). Files kebab-case, no barrels, English identifiers and output. No application schema change and
no Drizzle migration: the tool owns schema `v1_etl` (research R4). V1 is read-only. Never put
password hashes, tokens, note text or file contents in outputs, fixtures or logs. Every V2 financial
rule comes from `@openmonetis/domain` (cents in `money.ts`, periods and recurrence expansion in
`transactions.ts`, invoice dates in `cards.ts`, default categories in `categories.ts`); conversions
never re-implement them. `export MSYS_NO_PATHCONV=1` before docker commands.

**Contracts**: every type and exported function signature is fixed in
[contracts/internal-types.md](contracts/internal-types.md) (created as code by T004a). Use those
names, parameters and return types exactly; output shapes are in
[contracts/output-formats.md](contracts/output-formats.md), CLI in [contracts/cli.md](contracts/cli.md).
